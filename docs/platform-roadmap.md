# Platform roadmap

Status as of 2026-11-08. This page covers Ubuntu/Debian, Windows, macOS, iOS and Android. It separates what has been observed from what is only prepared; "not verified locally (CI only)" means a workflow exists but no local run was possible, and the new desktop workflow has not run remotely yet.

## 1. Platform role

Courrier is a **both** app in the Établi Suite: mail, calendar and tasks are needed on every device, so the same offline workspace runs on desktops and phones.

- **Ubuntu/Debian, Windows, macOS** are for desk work: reading and triaging mail, planning in the calendar and task lists, writing longer notes, and running the explicit account refresh on a large screen with a keyboard.
- **Android and iOS** are for the move: reading cached mail and notes offline, checking the agenda, completing tasks and receiving reminders.

All platforms use the same local-first model (SQLite store, manual sync, credentials in the platform secret store). No platform depends on a project-operated service.

## 3. Architecture

**Now.** One Flutter/Dart code base (`lib/`) serves all five platforms; `android/`, `ios/`, `linux/`, `macos/` and `windows/` are thin native runners generated by Flutter 3.47.9. Platform services come from federated plugins. Where a plugin or OS service is missing, `lib/core/platform/platform_capabilities.dart` reports it and the UI shows a disabled control with an explanation instead of failing at runtime (tests in `test/core/platform/`).

Identity: application ID / bundle ID `dev.etabli.courrier` everywhere (Linux GTK application ID and WM class, macOS bundle ID, MSIX identity). Display name "Établi Courrier" on Android, Linux and Windows; "Courrier" on iOS and macOS (Apple display name, ASCII bundle and executable name `courrier`). Desktop icons are rendered from the suite icon `docs/_icons/icon-courrier.svg`; Android and iOS still ship Flutter's placeholder launcher icon.

**Desktop layout.** The shell already switches to a navigation rail at 720 px or wider, which every desktop window uses; the selected-destination icon in the rail was invisible and is fixed. Module screens still open details as full-page routes (mail folder → thread list → message). A two-pane list/detail layout is not a small change across seven modules and is planned as M6.

**Target.** Keep a single code base. Platform-specific behaviour stays behind `PlatformCapabilities` and small adapters (notification scheduling per OS, desktop OAuth redirect, Linux lock), so each gap in the table can be closed without forking UI code.

### Credentials, app passwords and OAuth per OS

- **Nextcloud** (calendar, contacts, tasks, notes, news) uses an app password that the user creates in Nextcloud (Settings → Security) and enters in Accounts. **IMAP** uses the account password or a provider app password; credentials are only sent after TLS/STARTTLS. This flow is identical on all platforms; only the secret store differs (table above).
- **Linux:** without a Secret Service provider or with a locked keyring, saving credentials fails and the account is not enabled; cached content stays available. Acceptance (M2) must check the message shown in that case.
- **macOS:** sandboxed with `com.apple.security.network.client` (added for IMAP/HTTPS). Keychain access in the CI build (ad-hoc signed, no team) is expected to fail until M4.
- **Windows:** secrets are bound to the Windows user account (DPAPI); a copied data folder cannot be decrypted by another user.
- **Microsoft 365 OAuth** stays disabled pending the project's Entra registration and device validation (see `PREFLIGHT.md`). When enabled: Android, iOS and macOS use AppAuth with the custom scheme `dev.etabli.courrier://oauth`; Windows and Linux need the system browser plus a loopback redirect (`http://127.0.0.1:<port>`, RFC 8252) registered in Entra as a desktop redirect URI. Any new dependency for that (browser launcher, local listener) must pass the license gate first.

## 4. Per-platform execution

### Ubuntu/Debian

- **Prerequisites:** `sudo apt-get install clang cmake ninja-build pkg-config libgtk-3-dev libsecret-1-dev dpkg-dev`, Flutter 3.47.9.
- **Run / build / package:**
  ```sh
  flutter pub get --enforce-lockfile
  flutter run -d linux
  flutter build linux --release --no-pub
  scripts/package-deb.sh          # build/deb/etabli-courrier_0.1.0_amd64.deb
  sudo apt install ./build/deb/etabli-courrier_0.1.0_amd64.deb   # test machine only
  ```
- **Package:** `.deb` (`/opt/etabli-courrier`, launcher `/usr/bin/etabli-courrier`, desktop entry and hicolor icons named `dev.etabli.courrier`, notices in `/usr/share/doc/etabli-courrier`). Dependencies come from `dpkg-shlibdeps`; built on Ubuntu 24.04 the package targets Ubuntu 24.04+ and Debian 13+ (64-bit `t64` library names). Later: Flatpak on Flathub for other distributions (Secret portal, notification portal); arm64 `.deb` on an arm64 runner. AppImage is not planned (it cannot declare the keyring dependency and has no update channel).
- **Signing:** none needed for a GitHub Release `.deb` (publish SHA-256 sums). An apt repository would need a project GPG key (owner decision).
- **CI:** `desktop.yml` → `linux`: build, 15 s headless launch, desktop-entry validation, `.deb` build and inspection, artifact `courrier-linux-deb`.
- **Acceptance:** on clean Ubuntu 24.04 and Debian 13 VMs (GNOME and KDE): install with apt; start from the application menu (icon, title); create a note and reopen it after restart; connect Nextcloud with an app password and IMAP, restart and confirm no password prompt (keyring); refresh; disconnect; behaviour without a keyring; uninstall leaves `~/.local/share/dev.etabli.courrier` in place (documented).

### Windows

- **Prerequisites:** Windows 10/11 x64, Visual Studio 2022 with "Desktop development with C++", Flutter 3.47.9.
- **Run / build / package:**
  ```powershell
  flutter pub get --enforce-lockfile
  flutter run -d windows
  flutter build windows --release --no-pub
  dart run msix:create     # build\windows\msix\etabli-courrier.msix (config in pubspec.yaml)
  ```
- **Package:** MSIX (preferred: clean install/uninstall, app identity for notifications, Microsoft Store or winget). The ZIP of `build\windows\x64\runner\Release` is a portable fallback and needs the Microsoft Visual C++ Redistributable. MSI is not planned because MSIX covers the same need. `msix` 3.18.0 is a development dependency (MIT, recorded in the license gate); it copies the Visual C++ runtime DLLs into the MSIX.
- **Signing:** a code-signing certificate (OV/EV certificate or Azure Trusted Signing). `msix_config.publisher` must equal the certificate subject; CI secrets e.g. `COURRIER_WINDOWS_PFX_BASE64` and `COURRIER_WINDOWS_PFX_PASSWORD` (or the Trusted Signing service principal). Alternative: Microsoft Store via Partner Center, where the Store signs.
- **CI:** `desktop.yml` → `windows`: build, ZIP with `LICENSE`/`NOTICE`/`THIRD_PARTY_LICENSES.md`, unsigned MSIX, artifact `courrier-windows`. Not verified locally (CI only).
- **Acceptance:** on clean Windows 11: install the signed MSIX without warnings; start; note journey; connect accounts and restart (credentials kept); Windows Hello app lock on/off; data folder location as decided; uninstall; SmartScreen reputation acceptable for the ZIP.

### macOS

- **Prerequisites:** a Mac with Xcode, Flutter 3.47.9.
- **Run / build / package:**
  ```sh
  flutter pub get --enforce-lockfile
  flutter run -d macos
  flutter build macos --release --no-pub
  # sign with Developer ID (hardened runtime), then:
  hdiutil create -volname 'Etabli Courrier' -srcfolder <folder with courrier.app> -format UDZO etabli-courrier.dmg
  xcrun notarytool submit etabli-courrier.dmg --keychain-profile <profile> --wait
  xcrun stapler staple etabli-courrier.dmg
  ```
- **Package:** DMG with Developer ID signing, hardened runtime and notarization; ZIP for CI review. Mac App Store optional later (sandbox already enabled).
- **Signing:** Apple Developer Program membership (shared with iOS), Developer ID Application certificate (`.p12` + password), App Store Connect API key (issuer ID, key ID, `.p8`) for `notarytool`, team ID; a Developer ID provisioning profile if the keychain entitlement requires it.
- **CI:** `desktop.yml` → `macos`: build, `codesign --verify`, ZIP and DMG, artifact `courrier-macos`. The app is ad-hoc signed and not notarized, so Gatekeeper blocks a normal double-click open. Not verified locally (CI only).
- **Acceptance:** on clean macOS 14 and 15: notarized DMG opens without warnings; IMAP/DAV traffic works in the sandbox; credentials survive restart (keychain); Touch ID app lock; reminder permission prompt and delivery; Xcode-generated `macos/Runner.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` committed, as for iOS.

### iOS

- **Build:** `flutter build ios --debug --no-codesign` (CI); release `flutter build ipa --release --export-options-plist=<plist>` on a Mac or CI runner with signing.
- **Package and channel:** IPA → TestFlight → App Store.
- **Signing:** Apple Developer Program, distribution certificate and App Store provisioning profile for `dev.etabli.courrier` (or an App Store Connect API key for automatic signing); App Store listing, privacy policy URL, privacy labels, export compliance (standard HTTPS/TLS only).
- **CI:** `application.yml` → `ios` (unsigned). A manual signed job like `release-apk.yml` is added in M10.
- **Acceptance:** TestFlight build on a physical iPhone: note journey, account connect and restart, Face ID/passcode lock, reminders delivered at the scheduled time and after reboot; App Review passed.

### Android

- **Build:** `flutter build apk --release --split-per-abi --no-pub` and `flutter build appbundle --release --no-pub` with the ignored `android/keystore.properties`, or the manual `release-apk.yml` workflow.
- **Package and channels:** signed APKs on GitHub Releases; AAB on Google Play (Play App Signing); F-Droid from the prepared `fastlane/metadata/android` (NonFreeNet anti-feature note in `FDROID_NONFREENET.md`; F-Droid builds and signs from source unless reproducible builds are set up).
- **Signing:** `COURRIER_KEYSTORE_BASE64`, `COURRIER_STORE_PASSWORD`, `COURRIER_KEY_ALIAS`, `COURRIER_KEY_PASSWORD` in the `release` environment; Google Play Console account.
- **CI:** `application.yml` → `android`; `release-apk.yml` (manual, prepares artifacts only).
- **Acceptance:** the open gates in `docs/refinement-2026-10.md`: notification permission and delivery, lock lifecycle, live accounts, upgrade from v0.1.0, physical device.

## 5. Milestones

1. **M1 — Desktop CI green.** Push `desktop.yml`; fix any Windows/macOS compile or packaging failure. *Exit:* one green run on `main` with artifacts `courrier-linux-deb`, `courrier-windows` (ZIP + MSIX) and `courrier-macos` (ZIP + DMG); results recorded in `docs/current-status.qmd`.
2. **M2 — Ubuntu/Debian acceptance.** Run the Linux acceptance list on Ubuntu 24.04 and Debian 13 VMs, GNOME and KDE. *Exit:* written evidence (versions, steps, outcome) and fixes for any failure, including a clear message when no keyring is available.
3. **M3 — Windows acceptance (unsigned test machine).** Run the ZIP and a test-signed MSIX; decide the data-folder name (CompanyName/ProductName) before any user stores data. *Exit:* Windows checklist passed except signing items.
4. **M4 — macOS acceptance on a Mac.** Build locally, add the keychain entitlement (or decide otherwise) with team signing, confirm network, keychain, Touch ID and notifications; commit the generated `Package.resolved`. *Exit:* macOS checklist passed with a locally team-signed build.
5. **M5 — Desktop reminders.** Windows: initialise the plugin with AppUserModelID `dev.etabli.courrier`, schedule one toast per occurrence and re-arm on start, then enable `scheduledReminders` for Windows. Linux: in-app scheduler while Courrier runs plus optional XDG autostart. *Exit:* capability flags flipped with tests; delivery observed on Windows 11 and Ubuntu.
6. **M6 — Desktop layout.** Two-pane list/detail above about 1000 px for mail, notes, contacts and feeds; keyboard shortcuts (refresh, new note, search); minimum window size. *Exit:* widget tests at 1280 × 800 and reviewed screenshots; phone layout unchanged.
7. **M7 — Linux lock.** Decide between the existing PBKDF2 `PinAppLockGuard` (secret in the keyring) and no lock on Linux; implement and test. *Exit:* `deviceAuthentication` remains false, a separate Linux lock path is tested, or the decision to keep it disabled is recorded.
8. **M8 — Signed desktop releases.** Manual workflow like `release-apk.yml` that signs the MSIX, signs and notarizes the DMG, builds the `.deb` and writes `SHA256SUMS`; maintainer publishes a GitHub Release after review. *Exit:* signed artifacts install without OS warnings on clean machines.
9. **M9 — Microsoft 365 on desktop** (after the mobile Microsoft 365 gate). AppAuth on macOS; loopback redirect on Windows/Linux after license review; Entra desktop redirect URI. *Exit:* sign-in, refresh and sign-out tested on each desktop OS against the project tenant.
10. **M10 — Mobile release tracks.** Replace the placeholder launcher icons; iOS signed job → TestFlight → App Store; Android signed release → GitHub Releases, Google Play, F-Droid submission. *Exit:* listed builds accepted by each channel.
11. **M11 — Wider desktop distribution (optional).** Flatpak/Flathub, arm64 Linux, winget manifest, Homebrew cask. *Exit:* each channel accepted with automated updates from releases.

## 6. Owner decisions and prerequisites

- **Apple:** Apple Developer Program membership (iOS and macOS), Developer ID Application certificate, App Store Connect API key for notarization, App Store listing and privacy policy URL.
- **Windows:** code-signing route (OV/EV certificate, Azure Trusted Signing or Microsoft Store via Partner Center) and the publisher subject; `msix_config.publisher_display_name` is currently "R. Heller".
- **Windows data folder:** currently `%APPDATA%\R. Heller\Établi Courrier` (from the version resource's CompanyName/ProductName). Changing it after release needs a data migration.
- **Visual C++ runtime:** confirm that redistributing Microsoft's runtime DLLs inside the MSIX is acceptable under the project's licensing policy (the Dart license gate does not cover it).
- **Google Play:** Play Console account; **F-Droid:** go/no-go for submission with the NonFreeNet note.
- **Linux channels:** GitHub Releases only, or also an apt repository (GPG key) and/or Flathub.
- **Linux lock:** PIN-based lock or none (M7).
- **Display names:** "Établi Courrier" (Android/Linux/Windows) vs "Courrier" (iOS/macOS); unify if preferred.
- **Microsoft 365:** project Entra registration with mobile and desktop redirect URIs (`PREFLIGHT.md`).
