## Changes

Reminders now use one shared coordinator on supported platforms. Existing permission allows startup, foreground resume and committed calendar/reminder/task changes to refresh schedules. No permission dialog appears automatically. Concurrent changes queue another refresh, failures appear in the workspace, and Reminders → Reload uses the same coordinator. Existing due notifications remain pending until OS delivery, including delayed inexact alarms, without scheduling past alarms again; completed or deleted records are removed. Apple schedules retain the nearest 60 entries and the complete agenda stays visible; the Reminders screen explains that opening the app replenishes later entries. Android keeps its existing uncapped plan.

The Android source audit confirmed disabled backup/device transfer, no cleartext traffic, a fragment activity for biometric authentication, boot receivers and notification/exact-alarm permission declarations. Exact-alarm denial retains the existing inexact fallback.

Windows CI exposed an unrelated `local_auth_windows` build error: version 1.0.11 requests standard C++20 and legacy `/await` together. The first flag-only fix exposed a second upstream extension: a coroutine returned with `return` instead of `co_return`. The verified 1.0.11 source is now included under `third_party/local_auth_windows` with both CMake targets using standard C++20 and the coroutine returning correctly. Only those two upstream files differ; the BSD license and Dart API are retained. A transitive path override selects the reviewed source. Microsoft documents that standard coroutines require no `/await` in C++20 and that the option is deprecated in Visual Studio 2026: [compiler documentation](https://learn.microsoft.com/en-us/cpp/build/reference/await-enable-coroutine-support?view=msvc-170). The next exact-commit Windows build must verify the complete application.

## Android Studio setup

Use the pinned Flutter 3.47.9, Android SDK 36 and JDK 17 for parity with CI. Open the Flutter repository after `flutter pub get --enforce-lockfile`, or open `android/` for native Gradle inspection. Select JDK 17 in Android Studio's Gradle JDK setting; do not commit a personal absolute JDK path.

Android Studio 2026.2 ships JBR 25 on the audited Mac. This is especially relevant to Vitrine's Gradle 8.14.3: Java 25 runtime support starts at Gradle 9.1, according to the [Gradle compatibility matrix](https://docs.gradle.org/current/userguide/compatibility.html). Courrier uses Gradle 9.1/AGP 9.0.1, but JDK 17 keeps all suite projects consistent. Flutter may prefer Android Studio's bundled JDK over JAVA_HOME; its explicit local `jdk-dir` setting must agree with the IDE. The existing Kotlin/legacy-DSL compatibility flags remain required by the pinned Flutter/plugin setup; their AGP 10 migration warnings are not suppressed.
